Ponto de partida

Hoje existem dois sistemas, não um

O site principal e o Feirão Online cresceram em paralelo. O Feirão já provou, em produção, todos os padrões que faltam no site principal — só que isolados dentro de feirao/.

🌐 Sistema Web principal
9 páginas públicas + 1 painel administrativo, sem conceito de "papel" além de visitante e admin
  • index.html · imoveis.html · imovel.html
  • simulador.html · reserva.html · chat.html
  • ebook-financiamento-servidor-publico.html
  • marketing.html — existe, nunca foi implantado
  • admin.html — painel único, técnico/transversal
🎪 Feirão Online (feirao/)
Backend único (Apps Script + Sheets, 28 abas) e 5 dashboards de papel já em produção
  • feirao/cliente/dashboard-feirao-lead.html
  • feirao/agente/dashboard-agente.html
  • feirao/consultor/dashboard-feirao-atendente.html
  • feirao/diretoria/dashboard-diretor-wal.html
  • feirao/viabilizador/dashboard-viabilizador-wal.html
⚠️ Consequência prática: um lead que entra por reserva.html some assim que fecha o navegador — não existe painel de cliente fora do Feirão. Um corretor sem evento ativo não tem onde trabalhar. E o marketing.html foi desenhado sem nenhuma conexão com os dados reais de leads que já existem nas planilhas do Feirão.
O que muda

Nove papéis, um único Sistema Web

Clique em cada card para ver o que é novo, o que já existe e qual dashboard do Feirão serve de modelo. Verde = painel novo · Dourado = já existe e recebe ajustes (promoção ao site principal, gate de OTP, tela própria) · Cinza = mantém como está. Os oito papéis com dashboard próprio compartilham o mesmo cadastro único — ver seção 6. O Visitante não tem dashboard, mas ganha um gate de e-mail nas ações-chave que alimenta esse mesmo cadastro.

Estrutura de pastas

Novo mapa de arquivos proposto

As páginas públicas não mudam de lugar. Os painéis novos entram numa pasta painel/ — mesmo padrão de organização que feirao/ já usa por papel — e todos compartilham o backend que já existe em feirao/shared/.

Como os papéis se conectam

Da campanha de marketing ao contrato assinado

O mesmo lead atravessa vários painéis — cada um lê e escreve nas mesmas abas da planilha operacional, sem precisar de um "Feirão" ativo para existir.

Preparando o futuro

O que já é, sem perceber, um banco de dados

A planilha "WAL Feirão — Dados Operacionais" já tem 28 abas organizadas como tabelas relacionais (feirao/shared/apps-script-feirao-operacional.gs). Migrar para um banco de dados real não exige redesenhar nada — exige trocar o motor, mantendo o mesmo contrato.

💡 O ponto-chave: os dashboards nunca falam diretamente com o Google Sheets — eles chamam uma URL de API (feirao_listar_leads, feirao_reserva, etc.) que hoje é respondida pelo Apps Script. No dia da migração, essa mesma URL passa a ser respondida por um backend real (Node/Postgres, por exemplo) com as mesmas ações — os 9 painéis não precisam saber que a troca aconteceu.
Ideia do Antonio · 01/08/2026

Um cadastro único para todos os dashboards

Hoje o acesso é fragmentado — PIN de Diretoria/Viabilizador na aba AUTORIZADOS, PIN de Atendente/Gerente na aba ATENDENTES, cadastro de Agente na aba AGENTES, cada um num lugar. A proposta: uma única planilha de usuários (chave = e-mail) e um catálogo de dashboards, para que um botão "ACESSAR MEU DASHBOARD" saiba sempre para onde levar quem está entrando.

📇 Aba nova · USUARIOS
Cadastro único — um registro por pessoa, qualquer que seja o papel
  • 🔑 Email — chave de acesso e de login (OTP)
  • Nome completo · Telefone
  • Dashboards — lista, uma pessoa pode ter mais de um
  • Dashboard padrão — o que abre no botão principal
  • Status — ativo / inativo / pendente de aprovação
  • Construtora/Empresa — quando fizer sentido para o papel
  • Cadastrado por · Data de cadastro · Último acesso
🗂️ Aba nova · DASHBOARDS
Catálogo dos painéis que o sistema possui — hoje e no futuro
  • 🔑 Id_Dashboard — ex.: DIRETORIA, CORRETOR_AUTONOMO
  • Nome de exibição · Ícone
  • Rota/arquivo — ex.: painel/corretor/dashboard-corretor.html
  • Status — ativo / em construção / desativado
  • Ordem de exibição
💡 Adicionar um 10º dashboard no futuro vira uma linha nova nesta aba — não exige mexer no código de login/roteamento.

Como funciona o botão "Acessar meu Dashboard"

👑 Nova função da Diretoria: o painel da Diretoria ganha uma tela de Gestão de Usuários & Dashboards — cadastrar/editar/inativar pessoas, definir qual(is) dashboard(s) cada e-mail acessa, e manter o catálogo de dashboards atualizado. É a mesma ideia do cadastro de PIN que já existe hoje em acompanhamento-pre-cadastro.html, só que unificada para os nove papéis em vez de espalhada. Isso já estava previsto no status "pendente de aprovação" da aba USUARIOS: é a Diretoria quem libera o acesso de novos Agentes Parceiros, e confirma o de novos Agentes/Corretores Autônomos que o Gerente Comercial cadastrar — ver o card Diretoria na seção 2.
🔓 De onde vem o primeiro registro do Cliente: o gate de e-mail + OTP que o card Visitante/Público (seção 2) passa a ter no Simulador, na Reserva, no Consultor IA, no "Ver Todos", no E-book e no "Quero ser Contactado" do imovel.html é o mesmo mecanismo de OTP do Lead do Feirão — e é ele quem cria o primeiro registro do visitante como Cliente em USUARIOS/PARTICIPANTES, antes mesmo de ele abrir o próprio painel.
✅ Decidido com o Antonio (04/08/2026): o campo Dashboards fica como lista (não um valor único) — uma mesma pessoa pode acumular papéis com o tempo, como um Corretor que vira Gerente Comercial, ou um Gerente que também quer enxergar a visão da Diretoria.
